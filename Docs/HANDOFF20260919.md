### A real bug found and fixed — `is_admin()` had never worked

Found while running check 2, and the most consequential thing to come out of
the day.

`is_admin()` joined `admins.phone` to `profiles.phone`. **Every row in
`admins` has `phone` null** — the app's Add Admin path writes only the proxy
email and leaves phone null. A null never matches, so the function returned
false for everyone, always, on both projects, since first release.

What that disabled:

- `admin_read_completions` never fired, so the Admin Review tab showed an
  admin only their **own** acts — 78 of 233 on staging, and production showed
  the same shape.
- `admin_delete_completions` never fired either.
- The `is_admin()` branch of the "own rows" policy was dead.

In plain terms: **nobody could moderate anyone else's content.** That matters
independently of the dashboard, because moderation is something Apple asked
about during review.

Fixed with `coalesce(a.phone, split_part(a.email, '@', 1))` — deliberately not
a backfill of `admins.phone`, since the insert path would reintroduce null on
the next admin added. Applied by hand to both projects and recorded in
`supabase/migrations/20260919_fix_is_admin.sql`.

Verified after: staging Review went 78 → 233; production showed 17, matching
`select count(*) from completions`.
