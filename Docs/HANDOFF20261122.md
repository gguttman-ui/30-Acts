## 3. Standard SQL (Supabase SQL Editor, production, choose "No limit")

**List all current users (newest first, real emails):**

```sql
select
  u.created_at,
  coalesce(p.first_name, u.raw_user_meta_data->>'first_name') as first_name,
  coalesce(p.last_name, u.raw_user_meta_data->>'last_name') as last_name,
  split_part(u.email, '@', 1) as phone,
  coalesce(
    nullif(trim(p.contact_email), ''),
    nullif(trim(w.email), ''),
    c.email,
    case when p.email not like '%@phone.30acts.app'
          and p.email not like '%.internal'
         then nullif(trim(p.email), '') end
  ) as email,
  case
    when nullif(trim(p.contact_email), '') is not null then 'app'
    when nullif(trim(w.email), '') is not null then 'waitlist'
    when c.email is not null then 'contacts'
    when p.email not like '%@phone.30acts.app'
     and p.email not like '%.internal' then 'app'
    else 'none'
  end as email_source,
  u.last_sign_in_at
from auth.users u
left join public.profiles p on p.id = u.id
left join lateral (
  select email
  from public.waitlist w
  where w.phone = split_part(u.email, '@', 1)
  order by w.created_at desc
  limit 1
) w on true
left join public.admin_contacts c on c.phone = split_part(u.email, '@', 1)
order by u.created_at desc;
```

**Users by streak (current streak = consecutive days ending today or yesterday, Chicago date, from any Start over):**

```sql
with today as (
  select (now() at time zone 'America/Chicago')::date as t
),
acts as (
  select distinct c.user_phone, c.local_date::date as d
  from public.completions c
  where not public.is_test_phone(c.user_phone)
),
islands as (
  select user_phone, d,
         d - (row_number() over (partition by user_phone order by d))::int as grp
  from acts
),
runs as (
  select user_phone, min(d) as start_d, max(d) as end_d, count(*) as len
  from islands
  group by user_phone, grp
),
people as (
  select split_part(u.email, '@', 1) as phone,
         coalesce(p.first_name, u.raw_user_meta_data->>'first_name') as first_name,
         coalesce(p.last_name,  u.raw_user_meta_data->>'last_name')  as last_name,
         (p.last_restart_at at time zone 'America/Chicago')::date as restart_d
  from auth.users u
  left join public.profiles p on p.id = u.id
)
select
  pe.first_name,
  pe.last_name,
  r.user_phone as phone,
  coalesce(max(case when r.end_d >= (select t from today) - 1
                    then (r.end_d - greatest(r.start_d, coalesce(pe.restart_d, r.start_d)) + 1)
               end), 0) as current_streak,
  max(r.len) as best_streak,
  sum(r.len) as total_acts,
  max(r.end_d) as last_act
from runs r
left join people pe on pe.phone = r.user_phone
group by pe.first_name, pe.last_name, r.user_phone
order by current_streak desc, best_streak desc, last_act desc;
```

## Lessons from 26 October

- **A Settings save can undo an app-open sync.** Anything the app copies on open (time zone) must not be overwritten by a later save that only knows the home value.
- **Android trims a paste to the box's maxLength before the app sees it.** Never limit a code box; filter in code. People paste the whole text message.
- **The emulator has no real SMS, camera or microphone.** Test those on the Moto.
- **On Android, "Install succeeded" on expo.dev is the build status, not an install.** The APK must be opened from Files > Downloads; Play Protect blocks it until "More details > Install anyway".
- **On the Moto, apps can use only the fingerprint** ("Verify it's you in apps: Using fingerprint"); Face Unlock only unlocks the phone.
- **Reproduce on staging, never on a real user's data**, even when the report comes from production.
- **Never act right after closing a Modal on iPhone** (navigate, open another pop-up). Wait for onDismiss; one animation frame is not enough for a 300 ms fade. A timing bug can pass a test and still hit real users.

## Lessons from 19-25 October

- **Several rows with day_number 1 break `maybeSingle()` lookups** - look acts up by id or date, never by day number.
- **Profile time zone is not where the person is** (David's profile is Arizona while he was in NY). Date acts by the phone.
- **iPhone Mail does not load web images while composing** - attach the card instead.
- **Look users up by phone, not name** (David's profile name is stored as "Dave " with trailing spaces).
- **Reminder time zone lives in `auth.users.raw_user_meta_data->>'timezone'`** - send-reminders never reads profiles.iana_timezone. Read the sender before blaming a field.
- **A reminder only sends when reminder_hour is a number.** The Settings card shows 09:00 as a default even when nothing is saved - check the database, not the screen.
- **Europe and the US change clocks on different dates** (Europe 25 Oct, US 1 Nov): for that week Vienna is 6 hours ahead of Chicago, not 7.
- **Before changing compliance copy, check the Twilio registration and HELP reply** - they must agree with the app.
