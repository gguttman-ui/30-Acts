## For David — start here

Everything below is on the `preview` channel. Two ways in, and **which one you
use changes what you can test**:

**Option A — OTA (fastest).** If you already have a preview build, force-close
the app and open it twice. First launch downloads, second applies.

**Option B — install the new build.** Delete the old app off your iPhone first
(long-press → Remove App → Delete App), then install from the EAS link.

**The difference:** a new native module (`expo-mail-composer`) was added today.
On the OTA path your existing binary does not have it, so **Email will fall back
to the share sheet with the card attached** instead of rendering the picture
inside the email body. Everything else behaves identically. If you want to test
the inline email, you need Option B.

**Before reporting anything, check the Settings build stamp.** If it says
"update embedded," the OTA never applied and you are looking at old code. This
has cost hours before.

## What changed today

### 1. Every share surface is the same component

`src/components/ShareButtons.js` is now the only share UI in the app. Six call
sites across four screens use it. Nothing re-implements the markup.

The layout is the one from "Act Completed!":

```
Spread the kindness — invite someone to join!

  (IG)   (FB)   (TT)   (X)          <- circular, brand-coloured

 [ 💬 Text ] [ 📧 Email ] [ ↗️ More ]
```

The certificate screen's big labelled tiles and its separate green "Share as
image" button are gone.

### 2. Every share sends the picture only

All seven buttons on all four screens now send the rendered card and nothing
else. No captions, no clipboard text, no alerts telling you to paste something.
The card already carries the day number, branding, hashtag, QR code and the line
explaining the QR.

**The card now renders even when no story was written** — previously it only
rendered with story text, which under picture-only would have meant nothing to
send at all.

### 3. The QR reaches every screen

Daily Act and History were rendering the card **without an invite URL**, and
`StoryCard` only draws the QR block when it has one. Their cards had no QR and
no "scan this" line. Both now generate the Branch invite link and pass it in.

### 4. Facebook was broken and is fixed

`tryFacebookShareDialog` existed in three screens and was **never called** — the
button was wired to a save-to-Photos-and-paste flow instead. Facebook now opens
its own composer with the picture already attached. The old flow remains as a
fallback for Expo Go or a phone without the Facebook app.

This needs a real build. In Expo Go the SDK is not linked, `canShow` returns
false, and you get the fallback — that is expected, not a bug.

### 5. Email renders the card in the body

Email uploads the card to the public `act-media` bucket under `share-cards/`,
then composes an HTML message pointing at it. An `<img>` needs a real URL —
email clients strip `data:` URIs — which is why hosting is involved.

Three fallbacks: no mail composer or a failed upload → share sheet with the file
attached; no share sheet → plain `mailto:`.

**Only on Option B.** On the OTA path this degrades to the attachment.

### 6. Sharing returns you to the calendar

After a successful share the app lands on the calendar rather than sitting on
the finished act screen.

- **Text / Email / More** — the sheet closes and you are on the calendar.
  Cancelling leaves you where you were.
- **Instagram / Facebook / TikTok / X** — these hand off to another app. iOS
  will not bring you back on its own; when you switch back yourself you are on
  the calendar.

### 7. Admin growth metrics

A "📈 Growth" card on the Admin page: Downloads, Signed in, Did 1+ act, 30 days
in a row. Fed by `admin_growth_stats()`, which was created and verified today.

### 8. PayPal copies the bracelet amount

PayPal's managed QR-code link accepts no amount parameter, so it opened with an
empty box. It now copies `6.95` to the clipboard and says so before opening.
Venmo already prefilled; Zelle already copied.

## Known and deliberate

- **Photo and video acts now share the branded card, not the user's own photo.**
  Daily Act and History used to prefer the user's media. The card is what
  carries the QR, so it wins. If this is wrong, the QR would have to be composed
  onto the photo instead — a different piece of work.
- **Text and Email do nearly the same thing** now that captions are gone; they
  differ only in the subject line. Worth deciding whether both buttons earn
  their place.
- **The referral link travels only inside the QR.** No tappable link in the
  message body any more, except in the HTML email.
- The old `src/components/ShareRow.js` (July) is dead code, imported nowhere.

## Still open before App Store submission

- **CO-1 $15 fee**, due around 9/16
- **Venmo charity profile refuses payments** — "You can't donate to this charity
  right now." Venmo-side, not an app bug.
- **Real SMS delivery has never been tested end to end.** Twilio toll-free
  `+18336996137` had rejected verification. The biggest untested thing here.
- **Test data inflates the Growth metrics.** The live RPC returns
  `{"signins": 11, "did_one_act": 9, "streak_30": 2}` — all seeded test
  accounts, and both 30-day "streaks" are fake. Decide before launch: delete
  test completions from production, or filter known test phones inside
  `admin_growth_stats()`.
- **`app_metrics.downloads` must read NULL at launch.** It was set to `1234`
  during testing — a placeholder from an example, not a real figure. Check:
  ```sql
  SELECT * FROM public.app_metrics WHERE key = 'downloads';
  ```
- **`app.json` version is still 1.0.0** with `runtimeVersion: appVersion`. That
  means OTAs reach binaries that may not support them — today's mail-composer
  change degrades gracefully, but the next one might not. Bump `version`
  whenever a native module changes.

## Things that keep costing time

- **Check the build stamp first**, every time a change appears not to have
  taken effect.
- **PowerShell 5.1 has no `&&`.** Run commands on separate lines. And a `$`
  inside double quotes interpolates — use single quotes.
- **Facebook cannot be tested in Expo Go.** A failure there proves nothing.
- **`HistoryScreen.js` contains `DayDetailScreen`**, a different file from
  `DailyActScreen.js`, with separate share code. Test both.
- **Do not "clean up" the `StoryCard` capture quirk** (`top: 0, left: 0`, 1px
  `overflow: hidden`). Fully off-screen views return blank captures on iOS. It
  looks like dead styling. It is not.
- **TestFlight and the App Store share one binary and channel.** A `production`
  update reaches real users with no gate. Test on `preview` first.
