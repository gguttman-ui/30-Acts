## Shipped this session

### 1. Dashboard streak pages — final rules
The pager now follows one consistent set of rules, chronological left → right:

| What | Where it goes |
|---|---|
| Short streaks that never hit 30 | **Packed together** on a shared `EARLIER STREAKS` page, oldest first, one blank tile between streaks, 30 tiles per page |
| A completed 30-day streak | **Its own page**, labelled `STREAK · Completed · <start>–<end>` |
| Days past 30 (day 31, 32, …) | **A further page**, filling slots 1, 2, … of a fresh 30-slot board, labelled `STREAK · LAP 2 · <dates>` |
| Today | The interactive board on the far right, with the **+** tile |

Worked example — six short May/June streaks (2, 3, 1, 5, 4, 7 days) followed by a 32-day streak:

- **Page 1** — `EARLIER STREAKS`, 27 slots (22 acts + 5 separators)
- **Page 2** — `STREAK · Completed · Jul 5–Aug 3`
- **Page 3** — `STREAK · LAP 2 · Aug 4–Aug 5` (days 31 and 32 in slots 1 and 2 of 30)
- **Page 4** — today's board

**Bug found and fixed along the way:** a partial second lap was rendering as *today's live board*, complete with a **+** tile, even when the streak had died months earlier — so an abandoned 32-day streak looked like it was still running. It now checks that the last act was today or yesterday before treating a lap as live.

**Page dots** = the row of small dots under the grid, one per swipe page, with the active one stretched into a wider pill. They now wrap onto extra rows instead of running off the edge once a user accumulates a lot of pages.

### 3. Venmo — the white screen
**Cause:** the button opened `https://venmo.com/u/Actsofkindness30` in Safari. That profile page is login-walled and renders as a blank white page on mobile — which reads as a broken app.

**Fix:** both the Donate screen and the bracelet payment screen now open the **Venmo app's pay sheet** via `venmo://paycharge?txn=pay&recipients=Actsofkindness30`, falling back to the web link only when Venmo isn't installed. On the bracelet screen the deep link also prefills **amount = 6.95** and the note **"Kindness bracelet shipping"**, so nobody can send the wrong figure.

**Why it works over the air:** the code uses `Linking.openURL`, not `canOpenURL`. `canOpenURL` returns false for any scheme not whitelisted in `Info.plist`, which would have made this require a native build. `openURL` just rejects if the app is missing, and we catch that.

### 4. app.json — URL schemes (S2, not live yet)

## Gotchas worth remembering

- **PowerShell eats `$6`.** `--message "… $6.95 …"` in double quotes silently became `.95` (and killed one `eas update` outright with *"The variable '$6' cannot be retrieved"*). Use **single quotes** for any message containing a `$`.
- **TikTok needs All Photos.** iPhone Settings → TikTok → Photos → **All Photos**, or TikTok can't see the saved card.
- **Facebook "spinner on Post"** is a Facebook-app-side issue, not our code. Close and reopen FB, confirm login, retry. The picture is safe in Photos.
