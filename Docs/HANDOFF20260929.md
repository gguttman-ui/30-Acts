## Lessons from 29 September

- **Check the day of the week, not just the date.** The docs called 1 October a Wednesday for two days.
- **A checklist people work from belongs in a spreadsheet**, with a Done column and room around each step.
- **A QR code has to carry each influencer's own link**, so each influencer needs their own set of graphics.

## Standing rules

- One step at a time, each with an explicit verification. Every step says where it runs: **SQL Editor (staging/production)**, **PowerShell**, **dashboard**, **iPhone**, or **browser**.
- After each testing set, show both lists; keep list 2's "Waiting deployment" column, with waiting items at the end.
- No placeholder text in commands. Never paste secrets into chat.
- Avoid `||` in the SQL Editor; use `concat()`.
- Publish to `--branch production` only as the runbook says (Wednesday's approved exception); always pass `--environment`.
- Database dumps and snapshots stay out of the repo. Add files to git by name.
- Re-stage a file from the laptop immediately before reading it; re-read it after writing it.
- From 30 Oct, a new table in `public` needs explicit `grant` statements.
- Do not test deletion on production.
- Anything Gary pastes into email or Word is plain ASCII.
- Organization accounts use info@30actsofkindness.org, not personal email or phone.
